# Bestell-App

Bestell-App is an early frontend learning project created during my web development training. Its main purpose was to practise dynamic shopping-basket functionality, price calculations, application state, and interactive frontend behaviour with JavaScript.

## Setup

1. Clone or download the repository.
2. Open the project directory.
3. Serve the project with a local development server.
4. Open `index.html` in the browser.

Using a local development server is recommended so relative paths behave consistently.

## Features

- Dynamic rendering of restaurant dishes from JavaScript data
- Add dishes to the shopping basket
- Increase and decrease item quantities
- Remove individual dishes from the basket
- Dynamic subtotal calculation
- Delivery cost calculation
- Dynamic total price calculation
- Basket quantities persist in `sessionStorage` during the current browser session
- Simulated test-order workflow with confirmation feedback
- No real food orders are transmitted or stored
- Separate desktop and mobile basket behaviour
- Contact form with HTML validation and local demo confirmation
- Legal notice and privacy policy pages
- Navigation back to the start page from secondary pages
- Responsive layouts for mobile, tablet, desktop, and widescreen viewports

## Tech Stack

- HTML5
- CSS3
- Vanilla JavaScript

No frontend framework or build process is required.

## Application Logic

Dish data is stored in `js/db.js`. The menu and basket markup are generated by template functions in `js/template.js`. `script.js` manages application state, basket interactions, price calculations, responsive basket behaviour, test-order feedback, and basket persistence through `sessionStorage`.

`js/contact.js` handles the contact form locally. Entered form data is validated in the browser and is not transmitted to an external form service.

`js/page.js` resets restored scroll positions when pages are loaded so navigation and reloads start at the top of the page.

## Responsive Design

The application has been tested across viewport widths from **320 px to 3440 px**. The responsive layout uses dedicated mobile and tablet breakpoints together with scalable large-desktop and widescreen rules.

From **1440 px** and again from **1920 px**, selected layout dimensions, typography, navigation elements, dish cards, basket content, footer content, and other interface elements scale progressively instead of switching abruptly to fixed larger sizes.
